- **The live-symlink hazard is active *during* execution** — `~/.claude/skills/*` track the checked-out commit, so keep all Phase 1 work on `kyle/trinity-v2-4` and avoid running concurrent reviews in downstream repos during the work (plan's Rollback section). - **Composition goldens genuinely change this time.** Phase 0's §4 reviewer-prompt.md edit needed no golden regeneration (`iterate-plan/examples/composition/` is deliberately built from synthetic stand-in content, immune to real prompt edits). **Phase 1 is different**: Q5's HEAD-blob register composition is a `bin/plan_runner.py` change — `compose_input()` itself gains a new register-reading step — so this *is* the kind of change the composition goldens exist to pin, and they genuinely need regenerating in the same commit. Don't assume Phase 0's "no regen needed" precedent carries over.
- **The four register-load result states are easy to under-specify identically to how Phase 0's own scope-classifier bugs happened.** Phase 0's code review caught three consecutive rounds of "prose says X, code does X for the easy case but not the edge case" (root-level docs not checked for zero directory depth; basename extraction using the wrong split direction) — all in a *much simpler* mechanism than Phase 1's four-state register loader (loaded / confirmed-absent / malformed / operational-failure). Build the reference-implementation-plus-fixture pattern Phase 0 ended up needing (`scope_classifier.py`+checker, `freeze_tracker.py`+checker) as a *starting* discipline for Phase 1, not something to retrofit after a lens catches the gap. The qa lens's Phase 0 pass-1 HIGH finding is the standing precedent: prose-only claims about control-flow logic get challenged.
- **R2/R3 from the plan** — don't let the reduced non-production budget become a hard cap (it's a default; explicit `--max-passes` always wins — already shipped and working); keep the hygiene checklist to its two items (also shipped).
- **Phase 0 §5 ships no stop machinery** — nothing may consult `introduced_by_pass` for control flow; acceptance greps for exactly this, and Phase 1 must not change that (Phase 1 populates the `accepted-risk`/`register-match` disposition keys the schema already reserved — see `tools/provenance-recipe.jq`'s docstring — but still consults nothing for control flow).
- **R6 from the plan** — plan-review proportionality has a weaker case than code-review proportionality (plans are cheaper to fix than code); the anti-criteria (never on trust-boundary content, never to avoid a small honest fix) and the expectation-calibration note (judged on plan-loop pass counts, not code-review pass counts) both transfer from the plan document directly into whatever Phase 1 writes into `iterate-plan/SKILL.md` — don't let them get lost in the port.

Don't treat a fully-fold-induced streak as a signal to rush toward Converge; treat it as this session did — surface the observation, keep evaluating each finding on its own merits.
